## 🎯 Descripción del Proyecto

Los estudiantes, en equipos de 4-5 personas, deben desarrollar una aplicación web completa usando el stack tecnológico del curso (React, TanStack Router, Tailwind CSS). La aplicación debe resolver un problema real y estar completamente funcional.

**Tecnologías requeridas**:
- React (con hooks)
- TanStack Router
- Tailwind CSS
- Git y GitHub (para colaboración)

---

## 📋 Criterios de Evaluación

### 1. Diseño y Arquitectura (20 puntos)

| Nivel | Descripción | Puntos |
|-------|-------------|--------|
| **Excelente (4)** | Arquitectura modular y escalable. Componentes bien separados. Uso apropiado de patrones de diseño. Código limpio y organizado. | 18-20 |
| **Bueno (3)** | Arquitectura funcional. Componentes separados pero con algunas redundancias. Código organizado. | 14-17 |
| **Satisfactorio (2)** | Arquitectura básica. Algunos componentes monolíticos. Organización aceptable pero mejorable. | 10-13 |
| **Insuficiente (1)** | Arquitectura confusa. Código duplicado. Falta de organización. Difícil de mantener. | 0-9 |

**Indicadores**:
- ✓ Separación de componentes por responsabilidad
- ✓ Uso de custom hooks cuando es apropiado
- ✓ Estructura de carpetas lógica
- ✓ No hay código duplicado significativo

---

### 2. Funcionalidad (25 puntos)

| Nivel | Descripción | Puntos |
|-------|-------------|--------|
| **Excelente (5)** | Todas las funcionalidades implementadas y funcionando correctamente. Sin errores. Flujo completo de usuario. | 22-25 |
| **Bueno (4)** | La mayoría de funcionalidades implementadas. Errores menores que no afectan el uso principal. | 17-21 |
| **Satisfactorio (3)** | Funcionalidades básicas implementadas. Algunos errores que afectan parcialmente el uso. | 12-16 |
| **Insuficiente (1-2)** | Funcionalidades limitadas o con errores críticos. No se puede usar la aplicación completamente. | 0-11 |

**Indicadores**:
- ✓ Todos los requisitos del enunciado cumplidos
- ✓ Manejo de errores apropiado
- ✓ Validación de formularios
- ✓ Estados de carga y error
- ✓ Flujo de usuario completo

---

### 3. Interfaz de Usuario (UI) y Experiencia de Usuario (UX) (20 puntos)

| Nivel | Descripción | Puntos |
|-------|-------------|--------|
| **Excelente (4)** | Diseño atractivo y consistente. Uso efectivo de Tailwind CSS. Responsive en todos los dispositivos. UX intuitiva. | 18-20 |
| **Bueno (3)** | Diseño limpio y consistente. Responsive en la mayoría de dispositivos. UX clara. | 14-17 |
| **Satisfactorio (2)** | Diseño funcional pero con inconsistencias. Responsive básico. UX aceptable. | 10-13 |
| **Insuficiente (1)** | Diseño descuidado. No responsive. UX confusa. Difícil de usar. | 0-9 |

**Indicadores**:
- ✓ Consistencia visual (colores, tipografía, espaciado)
- ✓ Responsive design (mobile, tablet, desktop)
- ✓ Accesibilidad básica (contraste, etiquetas)
- ✓ Feedback visual (hover, active, focus)
- ✓ Navegación clara

---

### 4. Código y Calidad Técnica (20 puntos)

| Nivel | Descripción | Puntos |
|-------|-------------|--------|
| **Excelente (4)** | Código limpio, bien comentado. Sin warnings de ESLint. Uso apropiado de TypeScript. Testing incluido. | 18-20 |
| **Bueno (3)** | Código limpio. Comentarios útiles. Algunos warnings menores. TypeScript básico. | 14-17 |
| **Satisfactorio (2)** | Código funcional pero con algunos comentarios faltantes. Varios warnings. TypeScript opcional. | 10-13 |
| **Insuficiente (1)** | Código desordenado. Sin comentarios. Errores de linting. Sin TypeScript. | 0-9 |

**Indicadores**:
- ✓ Convenciones de código consistentes
- ✓ Nombres de variables/funciones descriptivos
- ✓ Comentarios donde es necesario
- ✓ Sin errores de compilación
- ✓ TypeScript bien tipado (si aplica)

---

### 5. Colaboración y Git (15 puntos)

| Nivel | Descripción | Puntos |
|-------|-------------|--------|
| **Excelente (3)** | Historial de Git limpio. Commits atómicos y descriptivos. Pull requests bien documentados. Branching strategy clara. | 13-15 |
| **Bueno (2)** | Historial de Git aceptable. Commits razonables. Pull requests básicos. | 9-12 |
| **Satisfactorio (1)** | Historial de Git confuso. Commits grandes y no descriptivos. Sin pull requests. | 5-8 |
| **Insuficiente (0)** | Sin uso de Git o uso incorrecto. Todo en master. Sin historial claro. | 0-4 |

**Indicadores**:
- ✓ Uso de branches (feature branches)
- ✓ Commits frecuentes y pequeños
- ✓ Mensajes de commit descriptivos
- ✓ Pull requests con descripción
- ✓ Resolución de conflictos apropiada
